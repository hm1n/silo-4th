# PRD_다시 묻는 질문으로 복습을 돕는 학습 에이전트

이 문서는 학습자가 학습 에이전트에게 같은 개념을 다시 묻는 문제를 왜 풀어야 하는지, 그리고 2주 동안 무엇을 만들고 확인할지 정리해요. 디자인과 개발은 이 문서의 범위와 가설을 기준으로 진행해요.

**한 문장 요약:** 학습자가 같은 개념을 다시 묻는다는 사실을 아무도 확인하지 않고 있고, 그사이 학습자는 같은 개념에서 다시 막히고 학습 플랫폼은 학습 에이전트의 효과를 설명하지 못해요. 우리는 다시 물은 개념을 떠올리기 질문으로 돌려주는 학습 에이전트를 만들어, 두 문제를 함께 풀 수 있는지 확인해요.

### 용어

| 용어 | 뜻 |
| --- | --- |
| 학습 에이전트 | 학습자의 질문에 답하며 공부를 돕는 AI예요. 강의 플랫폼에 들어 있는 AI 도우미나 ChatGPT 학습 모드가 여기에 해당해요 |
| 범용 AI | ChatGPT처럼 학습만을 위해 만들지 않은 AI 서비스예요 |
| 막히다 | 학습자가 혼자서는 다음 단계로 진행하지 못하는 상태예요 |
| 다시 물은 개념 | 서로 다른 날의 대화에서 두 번 이상 물은 같은 개념이에요. 예: 월요일과 목요일에 각각 "LEFT JOIN이 뭐예요?"라고 물었다면 LEFT JOIN이 다시 물은 개념이에요 |
| 떠올리기 질문 | 답을 보지 않고 스스로 기억해서 답하게 하는 짧은 질문이에요. 예: "LEFT JOIN과 INNER JOIN의 차이를 한 문장으로 설명해 보세요" |
| 다시 묻는 비율 | 한 번 물었던 개념을 다시 물은 비율이에요. 이 문서에서는 문제가 실제로 있는지 확인할 때만 써요 |
| 확인 문제 | 실험 마지막 날에 학습자가 개념을 혼자 맞힐 수 있는지 보는 문제예요. 떠올리기 질문과 같은 개념을 묻지만 문장은 다르게 내요 |
| 혼자 떠올려 맞힌 비율 | 확인 문제를 낸 개념 중, 학습자가 답을 보지 않고 맞힌 개념의 비율이에요. 이 프로젝트의 핵심 지표예요 |

## 1. 학습자는 같은 개념을 여러 번 물어도 그 사실을 모르고 지나가요

지수 씨는 퇴근하고 한 시간씩 데이터 분석을 공부해요. 회사에서 데이터를 직접 뽑아 보고 싶어서 시작한 공부예요. (문제를 설명하기 위해 만든 인물이에요.)

강의를 듣다가 SQL 조인에서 막혔어요. 학습 에이전트에게 물어보니 금방 알기 쉽게 설명해 줬어요. "아, 이거구나." 지수 씨는 고개를 끄덕이고 다음 영상으로 넘어갔어요.

목요일에 비슷한 쿼리를 쓰다가 다시 막혔어요. 분명히 본 내용 같은데, 혼자서는 쿼리를 쓸 수 없었어요. 지수 씨는 새 대화 창을 열고 거의 같은 질문을 했어요. 다음 주에도 한 번 더 물었어요.

지수 씨는 자기가 같은 개념을 세 번 물었다는 사실을 몰랐어요. 알려 주는 사람도 없었어요. 그런데도 불편하다고 느끼지는 않았어요. 물어보면 10초 만에 답이 나오기 때문이에요.

대신 이런 생각이 점점 자주 들었어요.

> "이해한 것 같은데, 왜 혼자서는 안 되지?"

학습 에이전트와 공부해 본 사람이라면 한 번쯤 이런 생각을 해 봤을 거예요.

## 2. 학습자와 학습 플랫폼 모두 "다시 묻는 질문"을 확인하지 않아요

지수 씨와 비슷한 학습자는 많아요.

- AI와 함께 문제를 푼 246명에게 자기 점수를 예상해 보라고 했더니, 실제보다 평균 4점 높게 답했어요. 학습자는 생각보다 쉽게 "이해했다"고 느껴요.
- 대학생과 AI가 나눈 대화 574,740건을 분석했더니, 약 47%는 문제를 빨리 해결하고 넘어가려는 대화였어요. 이 수치는 AI 기업이 자기 서비스를 분석한 결과예요.

같은 상황을 학습 플랫폼 입장에서 보면 다르게 보여요.

학습 에이전트는 지수 씨의 질문에 세 번 모두 정확하게 답했어요. 답변 품질만 보면 문제가 없어요. 그런데 지수 씨는 한 달 뒤 강의를 끝까지 듣지 않고 멈췄어요. 학습 플랫폼은 지수 씨가 왜 멈췄는지 알 수 없어요.

학습 플랫폼에는 다른 어려움도 있어요.

- **비용을 설명해야 해요.** 한 국내 강의 플랫폼은 AI 호출 비용이 클라우드 비용의 23%라고 공개했어요. 그런데 학습 에이전트가 학습에 도움이 됐다고 말할 근거는 아직 "답을 정확하게 했다"뿐이에요.
- **답만 주는 서비스는 범용 AI와 경쟁하기 어려워요.** 문제 풀이 답을 팔던 Chegg는 2025년 3분기 매출이 43% 줄었고, 학생들이 ChatGPT를 대안으로 본다고 공시했어요.

학습자는 "또 막혔다"고 느끼고, 학습 플랫폼은 "문제가 없다"고 봐요. 두 상황에는 공통점이 있어요. **학습자가 같은 개념을 다시 묻는다는 사실을 학습자도 학습 플랫폼도 확인하지 않는다**는 점이에요.

같은 개념을 다시 묻는다는 것은 학습자가 그 개념을 아직 이해하지 못했다는 분명한 근거예요. 그런데 왜 아무도 이 근거를 확인하지 않는지는 아직 몰라요. 지금 생각할 수 있는 원인은 세 가지예요.

| 원인 후보 | 근거 | 근거 수준 |
| --- | --- | --- |
| 학습자는 답을 읽으면 이해했다고 느껴서, 복습할 필요를 느끼지 못한다 | AI와 문제를 푼 246명이 자기 점수를 실제보다 4점 높게 예상했어요 | 연구로 확인됨 |
| 학습자는 답을 읽기만 하고, 스스로 떠올려 보는 연습을 하지 않는다 | 180명 실험에서 글을 반복해 읽은 집단은 1주 뒤 40%를, 스스로 떠올려 쓴 집단은 61%를 기억했어요 | 연구로 확인됨. 단, AI 학습 상황은 아님 |
| 질문 기록이 대화마다 따로 저장돼서, 같은 개념을 다시 물었다는 사실을 알아채기 어렵다 | 대화 목록은 시간 순서로만 보여 줘요 | 작성자의 추론. 검증 필요 |

세 원인은 동시에 작용할 수도 있어요. 어느 원인이 가장 큰지는 5장의 첫째 주 인터뷰에서 확인해요. 예를 들어 학습자가 지난 대화를 쉽게 다시 볼 수 있는데도 보지 않았다면, 기록이 따로 저장되는 것보다 첫 번째 원인이 더 클 수 있어요.

우리가 제안하는 떠올리기 질문은 세 원인을 모두 다루는 방법이에요. 다시 물은 개념을 알려 주고(세 번째 원인), 스스로 떠올려 보게 하고(두 번째 원인), 떠올리지 못하면 아직 이해하지 못했다는 사실을 알게 해요(첫 번째 원인).

## 3. 다시 물었던 개념을 혼자 떠올려 맞히게 하는 것이 목표예요

> **목표: 학습자가 다시 물었던 개념을 며칠 뒤에 답을 보지 않고 맞힐 수 있게 하고, 그 변화를 학습 플랫폼이 숫자로 확인할 수 있게 해요.**

### 핵심 지표를 "혼자 떠올려 맞힌 비율"로 정한 이유

처음에는 "다시 묻는 비율"을 핵심 지표로 생각했어요. 같은 개념을 덜 다시 물으면 덜 막힌다는 뜻이라고 봤기 때문이에요. 그런데 이 숫자에는 세 가지 문제가 있었어요.

1. **숫자가 줄어든 이유를 알 수 없어요.** 학습자가 이해해서 덜 물었을 수도 있지만, 공부를 그만두었거나 다른 AI에게 물었을 수도 있어요. 좋아진 경우와 떠난 경우가 같은 숫자로 나타나요.
1. **우리가 원하는 결과를 직접 재지 않아요.** 학습자가 원하는 것은 "혼자 할 수 있게 되는 것"이에요. "묻지 않았다"는 것은 그 결과를 간접적으로 추측할 뿐이에요.
1. **2주 안에는 숫자가 거의 변하지 않아요.** 학습자 8명이 일주일 동안 같은 개념을 다시 묻는 횟수는 적어서, 차이가 나와도 우연인지 구분하기 어려워요.

그래서 핵심 지표를 **혼자 떠올려 맞힌 비율**로 바꿨어요. 다시 물었던 개념을 며칠 뒤에 물어봤을 때, 학습자가 답을 보지 않고 맞힌 비율이에요. 이 숫자는 "혼자 할 수 있게 됐는가"를 직접 보여 줘요. 그래서 학습자에게는 실력이 늘었다는 증거가 되고, 학습 플랫폼에는 "답을 정확하게 했다"보다 강한 학습 효과의 근거가 돼요.

### 지표 한눈에 보기

| 역할 | 지표 | 쉽게 말하면 |
| --- | --- | --- |
| 핵심 지표 | 혼자 떠올려 맞힌 비율 | 다시 물었던 개념을 며칠 뒤에 혼자 맞힐 수 있나요? |
| 보조 지표 | 떠올리기 질문 응답률 | 떠올리기 질문을 받으면 실제로 답해 보나요? |
| 문제 확인용 지표 | 다시 물은 개념이 있는 학습자 수 | 학습자가 정말 같은 개념을 또 물어보나요? |
| 지켜야 할 지표 | 학습 에이전트를 사용한 날수 | 떠올리기 질문이 번거로워서 떠나지는 않나요? |
| 나중에 볼 지표 | 강의를 끝까지 들은 비율, 다음 강의 구매 | 실력이 늘면 공부를 계속하고 다음 강의도 사나요? (서비스 공개 후) |

### 핵심 지표는 이렇게 재요

| 항목 | 내용 |
| --- | --- |
| 정의 | 확인 문제를 낸 "다시 물은 개념" 중, 학습자가 답을 보지 않고 맞힌 개념의 비율 |
| 계산식 | 맞힌 개념 수 ÷ 확인 문제를 낸 개념 수 × 100 |
| 세는 단위 | 개념 하나를 한 번만 세요. 학습자 한 명이 개념 5개를 가졌다면 5개를 세요 |
| 재는 시점 | 13~14일차에 재요. 마지막으로 그 개념을 물었거나 떠올리기 질문에 답한 날로부터 3일 이상 지난 뒤에 재요. 바로 물어보면 잠깐 기억한 것인지 구분할 수 없기 때문이에요 |
| 확인 문제 | 떠올리기 질문과 같은 개념을 묻지만, 문장은 다른 문제를 내요. 같은 문제를 다시 내면 답만 외운 것인지 구분할 수 없어요 |
| 진행 방법 | 15분 화상으로 진행하고, 학습자에게 검색이나 AI를 쓰지 말아 달라고 미리 안내해요 |
| 채점 방법 | 개념마다 정답 기준표를 미리 만들어요. 팀원 두 명이 따로 채점하고, 두 사람의 판단이 다르면 세 번째 팀원이 정해요. 부분적으로 맞힌 답은 틀린 것으로 세요 |
| 비교 방법 | 같은 학습자 안에서, 떠올리기 질문을 받은 개념 그룹과 받지 않은 개념 그룹의 비율을 비교해요. 두 그룹의 차이가 떠올리기 질문의 효과예요 |
| 따로 보는 경우 | 둘째 주에 학습 에이전트를 사용한 날이 2일 미만인 학습자는 결과를 따로 정리해요. 실험에 거의 참여하지 않은 사람의 결과가 섞이면 효과를 판단하기 어려워요 |
| 통과 기준 (제안) | 질문을 받은 그룹이 받지 않은 그룹보다 15%p 이상 높고, 8명 중 6명 이상에게서 같은 방향으로 나타나요 |

통과 기준을 15%p로 제안한 이유가 있어요. 2장에서 소개한 180명 실험에서는 스스로 떠올린 집단과 반복해 읽은 집단의 차이가 21%p였어요. 우리 실험은 떠올리기 질문을 하루에 하나만 보여 주므로, 그보다 낮게 잡았어요.

### 보조 지표는 이렇게 재요

| 지표 | 계산식 | 재는 시점 | 기준 (제안) | 보는 이유 |
| --- | --- | --- | --- | --- |
| 떠올리기 질문 응답률 | 답한 떠올리기 질문 수 ÷ 보여 준 떠올리기 질문 수 × 100 | 8~12일차 매일 | 60% 이상 | 학습자가 실제로 한 번 더 공부하는지 확인해요 |
| 다시 물은 개념이 있는 학습자 수 | 최근 2주 대화에서 다시 물은 개념이 1개 이상인 학습자 수 | 3~5일차 인터뷰 | 8명 중 4명 이상 | 문제가 실제로 있는지 확인해요 |
| 학습 에이전트를 사용한 날수 | 둘째 주 5일 중 학습 에이전트를 연 날의 평균 | 8~12일차 매일 | 평균 3일 이상 | 떠올리기 질문 때문에 학습자가 떠나지 않는지 확인해요 |

### 이 지표에도 한계가 있어요

- **참여자가 적어요.** 8명으로는 효과를 통계적으로 증명할 수 없어요. 이번 실험은 효과가 있는 방향인지 확인하는 것이 목적이에요.
- **실험에 참여하는 것만으로 공부를 더 할 수 있어요.** 두 그룹이 같은 학습자의 개념이라서 비교에는 영향이 적지만, 비율 자체는 실제 서비스보다 높게 나올 수 있어요.
- **채점에 사람의 판단이 들어가요.** 정답 기준표를 미리 만들고 두 명이 따로 채점해서 줄여요.

### 지표가 매출로 이어질 것으로 예상하는 순서

1. 학습자가 떠올리기 질문에 답하며 한 번 더 공부해요. (보조 지표)
1. 다시 물었던 개념을 혼자 떠올려 맞히게 돼요. (핵심 지표)
1. 혼자 할 수 있는 것이 늘어나서 강의를 끝까지 들어요.
1. 다음 강의를 사거나 구독을 이어가서, 학습 플랫폼의 매출이 늘어요.

1과 2는 2주 안에 확인해요. 3과 4는 서비스를 공개한 뒤에 확인해요. 이 순서는 아직 검증하지 않은 추론이에요.

## 4. 답을 개선하지 않고, 다시 물은 개념을 떠올리게 해요

지수 씨에게 필요했던 것은 더 좋은 답이 아니었어요. 학습 에이전트의 답은 이미 정확했어요. 지수 씨에게 필요했던 것은 아래와 같은 안내였을 거예요.

> "이 내용은 지난주에도 물어보셨어요. 답을 보지 말고 한번 떠올려 볼까요?"

### 하는 것

- 대화가 끝나도 질문 기록을 저장해요.
- 여러 대화에서 다시 물은 개념을 찾아요.
- 다음 날, 다시 물은 개념에 대한 떠올리기 질문을 하나 보여 줘요. 학습자는 답하지 않고 공부를 계속할 수도 있어요.
- 혼자 떠올려 맞힌 비율을 기록해서, 나중에 학습 플랫폼에 보여 줄 수 있게 해요.

### 하지 않는 것

| 하지 않는 것 | 이유 |
| --- | --- |
| 답변 품질 개선 | 지수 씨가 다시 막힌 이유는 답이 틀려서가 아니었어요 |
| 퀴즈 강제 | 퇴근 후에 반드시 풀어야 하는 퀴즈가 있다면 학습자는 학습 에이전트를 쓰지 않을 거예요 |
| 강의 제작자용 대시보드 | 여러 학습자의 기록이 충분히 모인 뒤에 검토해요 |
| 학습 경로 자동 추천 | 한 학습자의 기록만으로는 추천 근거가 부족해요 |

### 가설

아래 다섯 가지는 아직 확인하지 않은 가설이에요. 학습자에 대한 가설(1~3)이 맞아야 학습 플랫폼에 대한 가설(4~5)도 의미가 있어요. 그래서 1번부터 차례로 확인하고, 가설이 틀렸을 때 할 일도 미리 정해 둬요.

| 번호 | 가설 | 틀렸을 때 할 일 |
| --- | --- | --- |
| 1. 문제 | 학습자는 서로 다른 대화에서 같은 개념을 다시 묻는다 | 문제를 다시 정의해요 |
| 2. 행동 | 다시 물은 개념을 다음 날 떠올리기 질문으로 보여 주면 학습자가 답한다 | 질문을 보여 주는 시간이나 방식을 바꿔요 |
| 3. 학습 | 떠올리기 질문을 받은 개념은 받지 않은 개념보다 며칠 뒤 혼자 떠올려 맞히는 비율이 높다 | 떠올리기 질문의 형식을 바꿔요 |
| 4. 매출 | 혼자 떠올려 맞힌 비율이 높은 학습자는 강의를 끝까지 듣는 비율이 높다 | 판매 방식을 다시 검토해요 |
| 5. 구매 | 학습 플랫폼은 혼자 떠올려 맞힌 비율을 리포트로 받고 싶어 한다 | 비용을 낼 고객을 다시 정해요 |

## 5. 2주 동안 가설 1~3을 학습 에이전트로 직접 확인해요

다섯 가설을 2주 안에 모두 확인할 수는 없어요. 그래서 틀렸을 때 계획 전체를 바꿔야 하는 가설부터 확인해요.

- **가설 1(문제):** 이 가설이 틀리면 나머지 가설은 모두 의미가 없어요. 가장 먼저 확인해요. 이때 2장의 원인 후보 중 어느 것이 큰지도 함께 확인해요.
- **가설 2(행동)와 가설 3(학습):** 우리가 만들려는 기능의 핵심이에요. 간단하게 만든 학습 에이전트로 직접 확인해요.
- **가설 4(매출)와 가설 5(구매):** 실제 서비스와 더 많은 학습자가 필요해서 이번 2주에는 다루지 않아요.

이번 프로젝트는 디자이너, 개발자와 함께 학습 에이전트를 간단하게라도 직접 만드는 것까지가 범위예요. 그래서 2주를 다음과 같이 써요.

- **첫째 주:** 제품 책임자가 학습자 8명과 가설 1을 확인하는 동안, 디자이너와 개발자는 학습 에이전트를 만들어요.
- **둘째 주:** 같은 학습자 8명이 그 학습 에이전트를 직접 써요.

### 첫째 주 인터뷰에서 확인할 것

학습자가 자기 AI 대화 목록을 화면 공유로 보여 주면, 최근 2주 동안의 대화를 함께 봐요. 대화 원문은 받지 않고 질문의 주제와 날짜만 기록해요.

1. 다시 물은 개념이 있나요? (가설 1)
1. 다시 물었을 때, 전에 물었다는 것을 기억했나요? (원인 후보 3)
1. 기억했다면, 왜 지난 대화를 다시 보지 않고 새로 물었나요? (원인 후보 1, 2)

### 간단하게 만들 학습 에이전트

반드시 필요한 기능은 다섯 가지예요.

1. **대화 화면:** 학습자가 질문하면 학습 에이전트가 답해요.
1. **질문 기록:** 질문마다 날짜와 개념 이름을 함께 저장해요.
1. **다시 물은 개념 찾기:** 같은 개념 이름이 다른 날 두 번 이상 나오면 다시 물은 개념으로 판단해요.
1. **떠올리기 질문:** 학습자가 다음 날 처음 접속하면, 다시 물은 개념 중 하나로 떠올리기 질문을 보여 줘요. 건너뛰기 버튼도 함께 보여 줘요.
1. **측정 기록:** 학습자가 떠올리기 질문에 답했는지, 학습 에이전트를 연 날짜, 같은 개념을 다시 물었는지 저장해요. 각 개념이 떠올리기 질문을 받는 그룹인지도 함께 저장해요.

로그인, 강의 연동, 대시보드, 화면 완성도는 이번에 만들지 않아요. 로그인은 참여 코드로, 대시보드는 스프레드시트로 대신해요.

첫째 주 인터뷰에서 찾은 각자의 다시 물은 개념을 학습 에이전트에 미리 입력해 두면, 둘째 주 첫날부터 떠올리기 질문을 보여 줄 수 있어요. 일주일 동안 새 기록이 늘어나기를 기다리지 않아도 돼요.

### 역할별 2주 일정

| 기간 | 제품 책임자 | 디자이너 | 개발자 |
| --- | --- | --- | --- |
| 1~2일차 | 참여자 8명 모집, 인터뷰 질문 확정 | 대화 화면과 떠올리기 질문 화면 스케치 | 대화 화면과 질문 기록 저장 구현 |
| 3~5일차 | 인터뷰 진행, 가설 1 판단 | 인터뷰 함께 진행, 화면 확정 | 개념 이름 저장, 다시 물은 개념 찾기 구현 |
| 6~7일차 | 개념을 무작위로 두 그룹으로 나누기, 개념별 확인 문제와 정답 기준표 작성, 참여자 안내 | 학습자 1~2명과 써 보고 불편한 화면 수정 | 떠올리기 질문과 측정 기록 구현, 첫째 주 개념 입력 |
| 8~12일차 | 매일 응답률 확인, 가설 2 판단 | 사용 중 불편한 점 수집 | 오류 수정, 기록 점검 |
| 13~14일차 | 15분 화상으로 확인 문제 진행, 두 명이 따로 채점, 가설 3 판단 | 발표용 화면 정리 | 데이터 정리 |

떠올리기 질문은 한 학습자의 다시 물은 개념 중 한 그룹에만 보여 줘요. 그러면 참여자가 8명뿐이어도 같은 학습자 안에서 "질문을 받은 개념"과 "받지 않은 개념"을 비교할 수 있어요.

7일차까지 학습 에이전트가 준비되지 않으면, 떠올리기 질문을 메신저로 직접 보내요. 그러면 개발이 늦어져도 실험을 계속할 수 있어요.

### 14일차의 판단 기준

| 결과 | 다음에 할 일 |
| --- | --- |
| 8명 중 다시 물은 개념이 있는 사람이 4명 미만이에요 | 문제가 예상보다 작아요. 문제를 다시 정의해요 |
| 문제는 있지만 떠올리기 질문 응답률이 60% 미만이에요 | 질문을 보여 주는 시간이나 방식을 바꿔 1주 더 확인해요 |
| 문제가 있고, 응답률도 60% 이상이고, 질문을 받은 개념의 혼자 떠올려 맞힌 비율이 받지 않은 개념보다 15%p 이상 높아요 | 학습 에이전트의 첫 번째 공개 버전을 만들기 시작해요 |

판단 기준의 숫자(4명, 60%, 15%p)는 제안이에요. 각 지표의 자세한 계산 방법은 3장에 있어요. 실험을 시작하기 전에 팀이 함께 확정해요.

## 6. 시장 규모는 인터뷰에서 두 비율을 확인한 뒤에 계산해요

국내 이러닝 매출은 5조 5,946억 원이고, 그중 개인이 지출한 금액은 2조 9,717억 원이에요(2023년). 개인 이용자가 가장 많이 듣는 분야는 지수 씨처럼 직무를 위한 교육이에요.

이 프로젝트가 다루는 시장은 아래 식으로 계산해요. 두 비율은 아직 공개 자료에서 찾지 못했어요. 그래서 인터뷰와 설문으로 확인한 뒤에 채워요.

> 개인 이러닝 지출 2조 9,717억 원 × 직무 교육 비중 × 학습 에이전트와 함께 공부하는 학습자 비율

## 7. 아직 확인하지 못한 것이 네 가지 있어요

- **다시 묻는 이유:** 학습자가 개념을 이해하지 못해서가 아니라 문법을 잊어서 다시 묻는다면, 복습보다 빠르게 다시 찾아보게 해 주는 기능이 더 맞아요.
- **비용을 낼 고객:** 지금은 학습 플랫폼을 고객으로 보고 있어요. 학습자가 직접 비용을 낼지는 아직 확인하지 않았어요.
- **범용 AI와의 차이:** ChatGPT 같은 범용 AI도 지난 대화를 기억하는 기능을 제공해요. 다시 물은 개념을 찾아 떠올리기 질문으로 보여 주는 기능이 충분한 차이인지 확인해야 해요.
- **개인정보:** 대화 기록에는 개인적인 내용이 포함될 수 있어요. 실험에서는 대화 원문을 받지 않고 주제와 날짜만 기록해요. 학습 플랫폼에는 개인을 알아볼 수 없는 비율만 보여 줘요.
