# 스프린트 1 기술 스택 결정

## 배경

Linear 프로젝트 "스프린트 1: 이해 확인과 기록 검증"의 문서로 문제 정의와 범위가 바뀌어, PRD를 근거로 쓴 기존 기술 스택을 다시 정했다. 01 브리프에 따라 "어떻게 동작하게 만드는지"는 개발자가 DRI이므로, 개발자의 영역에 속하는 항목만 정했다. PO나 디자이너가 DRI인 항목은 정하지 않았다.

## 확정한 것

| 영역 | 결정 | 이유 |
| --- | --- | --- |
| DB | Neon Postgres를 쓴다 | 02 화면 흐름의 "남겨야 할 기록" 여섯 가지를 저장해야 하고, 다른 기기에서 같은 학습자로 이어지거나 문제를 풀다 닫은 뒤 이어서 풀려면 서버에 기록이 있어야 한다. PO가 SQL로 지표를 뽑을 수 있고, Vercel에 연결하기 쉽다 |
| DB 접근 | Drizzle ORM을 쓴다 | 스키마에서 타입이 나와 AI가 작성한 DB 코드의 오류를 컴파일 단계에서 잡을 수 있다. SQL을 직접 쓰면 결과 타입을 손으로 붙여야 하고, 컬럼 오타는 실행해야 드러난다. 스키마가 바뀌어도 스키마 파일을 고치고 반영하면 된다 |
| 학습자 유지 | 첫 화면에서 이메일을 입력하면 학습자를 찾거나 만들고, 학습자 ID를 서명한 httpOnly 쿠키에 저장한다 | 01 브리프에서 로그인을 만들지 않기로 했고, 02 화면 흐름에서 같은 이메일을 입력하면 같은 학습자로 이어지도록 정했다 |
| 출처 기록 | 첫 방문 때 `from` 값을 쿠키에 담아 두고, 이메일을 입력하면 학습자 기록에 저장한다. 이미 출처가 있는 학습자는 바꾸지 않는다. 팀은 `from=test`로 들어오고, 값이 없으면 `unknown`으로 남긴다 | 01 브리프와 03-1 진행 가이드에서 "다시 오는가"를 커뮤니티 집단으로만 판단하기로 해서, 학습자마다 출처가 하나로 고정되어야 한다 |
| 날짜 계산 | 시각은 UTC로 저장하고, 학습일은 "한국 시간에서 4시간을 뺀 날짜"로 한 함수에서만 계산한다. 테스트 학습자에게만 날짜 오프셋을 두어 하루를 당긴다 | 02 화면 흐름에서 하루의 시작을 새벽 4시로 정했고, 03-1 진행 가이드에서 테스트 학습자의 날짜를 당기는 방법은 개발자가 정하도록 했다. 실제 학습자에게는 영향이 없어야 한다 |
| 오류 알림 | Sentry를 쓴다 | 03 상세 일정에서 11/6에 오류 알림을 설정하고 오류가 나면 PO가 알 수 있어야 한다고 정했다. 서버와 브라우저 오류를 모두 잡을 수 있다 |
| 유지 | Next.js(App Router)와 TypeScript, Vercel, `@anthropic-ai/sdk`, Tailwind CSS를 그대로 쓴다 | 새 문서와 부딪치는 내용이 없다. 01 브리프에 따라 AI가 개념을 고르거나 문제를 만들지 않으므로 LLM은 질문에 답하는 데만 쓰고, 다른 LLM 연결 방식으로 바꿀 이유가 없다 |

## 제안

- 학습 자료는 단원마다 Markdown 파일로 저장소에 두고, 확인 문제는 JSON 파일로 받아 DB에 넣는다. 확인 문제를 고쳐도 배포 없이 DB만 바꾸면 된다. 01 브리프에서 학습 자료 파일 형식은 개발자와 PO가 함께 정하도록 했으므로, PO와 확정하기 전까지는 제안으로 둔다.

## 보류

- **AI 모델:** 11/2까지 같은 질문으로 모델을 비교한 뒤 정한다. 기능 동결(11/4) 뒤에는 모델을 바꾸지 않는다.
- **UI 컴포넌트:** 02 화면 흐름에서 학습 화면은 개발자가 기본 컴포넌트로 만들도록 했다. shadcn/ui를 도입할지는 디자이너와 상의한 뒤 정한다.

## 확인 필요

- 서명 쿠키 방식에서는 다른 사람의 이메일을 입력하면 그 사람의 기록에 이어진다. 보완 방법이 필요하고, 로그인을 도입할지는 PO와 논의한다.

## 정하지 않은 것

- 지표 추출 방식과 Google Sheets 사용 여부는 PO가 DRI라서 개발자가 정하지 않았다.
