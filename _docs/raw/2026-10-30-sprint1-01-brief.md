# 01 브리프

이번 스프린트에서 무엇을 왜 하는지, 무엇으로 판단하는지 정리한 문서예요. 착수할 때 한 번 읽어 주세요. 일하다가 "이걸 해야 하나?"라는 생각이 들면 이 문서로 돌아와 주세요.

> **AI와 주고받기만 하는 학습이 아니라, 정말 이해했는지 확인하고 그 기록을 남겨요. 이번 스프린트에서는 이게 학습자 개인에게 가치가 있는지를 먼저 검증해요.**

| 항목 | 내용 |
| -- | -- |
| 대상 | SQLD 제63회(11/14 토)를 준비하며 AI로 공부하는 사람 |
| 답할 질문 | 1. 학습자는 정말 이해했는지 확인받기를 원하는가? 2. 확인한 기록을 다시 찾아와 쓰는가? |
| 핵심 지표 | 기록 재방문 학습자 수 |
| 주요 날짜 | 10/30 착수, 11/4 기능 동결, 11/5 학습자에게 공개, 11/10 발표, 11/20 최종 결과 |

## 왜 이 문제를 푸나요

### 학습자가 겪는 일

AI에게 물어보고 설명을 읽으면, 학습자는 이해했다고 느껴요. 하지만 며칠 뒤 힌트 없이 문제를 받으면 혼자 풀지 못하는 경우가 있어요. 이 착각은 시험장에서야 드러나요. 그때는 이미 늦어요.

|  | 민수 | 지영 |
| -- | -- | -- |
| 한 일 | 월요일에 묻고, 목요일에 같은 걸 또 물었어요 | 월요일에 한 번 묻고, 이해했다고 생각해서 다시 묻지 않았어요 |
| 실제 상태 | 헷갈려서 확인한 것뿐이고, 문제를 내면 혼자 풀어요 | 문제를 내면 못 풀어요 |
| 도움이 필요한가요 | 아니요 | **예** |

우리가 도와야 하는 사람은 지영이에요. 그런데 지영은 자기가 모른다는 걸 모르기 때문에 불편을 느끼지 않아요. 그래서 시험을 앞둔 사람을 대상으로 해요. 시험을 앞둔 사람은 "내가 진짜 아는지" 이미 불안해하고 있어요.

### 확인과 기록이 왜 중요한가요

프로젝트의 가장 큰 목적은 학습자가 묻고 확인한 내용을 **데이터로 남겨**, 학습자 개인과 학습 플랫폼이 활용하게 하는 거예요. 그런데 확인을 거치지 않으면 데이터는 "무엇을 물었는지"에 그쳐요.

| 남는 데이터 | 대화만 할 때 | 확인까지 할 때 |
| -- | -- | -- |
| 무엇을 물었나 | 알 수 있어요 | 알 수 있어요 |
| 정말 이해했나 | 알 수 없어요 | 알 수 있어요 |
| 어디서 착각하나 | 알 수 없어요 | 알 수 있어요 |

이번 스프린트에서는 학습자 **개인**에게 가치가 있는지만 확인해요. 플랫폼이 이 데이터를 활용하는 일은 그다음에 다뤄요.

### 지금 아는 것과 모르는 것

| 구분 | 내용 |
| -- | -- |
| 아는 것 | 외부 연구에서 AI와 함께 문제를 푼 246명이 자기 점수를 실제보다 평균 4점 높게 예상했어요. 다만 우리 학습자에 대한 관찰은 아니에요 |
| 모르는 것 | 우리 학습자도 이해했다고 착각하는지 |
| 모르는 것 | 학습자가 확인받고 기록이 남는 것을 원하는지 |

솔직하게 말하면, 이 문제가 우리 학습자에게 있다는 근거는 아직 없어요. 이번 스프린트는 그 근거를 만드는 일이에요. 문제가 없다는 결과가 나와도 실패가 아니라 배운 거예요.

## 학습자가 겪는 경험

1. **들어와요.** 커뮤니티 게시글이나 지인이 보낸 주소로 들어와, 이메일, 시험 날짜, 저장 동의를 입력해요.
2. **공부해요.** 왼쪽 SQLD 학습 자료를 읽다가 오른쪽 AI에게 물어봐요. AI는 평소 쓰는 AI처럼 바로 답해요.
3. **다음 날 확인해요.** 학습 화면에 들어가기 전에 확인 화면이 떠요. "맞힐 자신이 얼마나 있나요?"를 먼저 고르고, 어제 공부한 단원의 문제를 풀어요. 문제에는 개념 이름이 나오지 않아요.
4. **결과를 봐요.** 자신감과 실제 결과를 나란히 봐요. "자신 있었는데 틀린 것"이 착각한 개념이에요.
5. **기록을 써요.** "내 이해 기록"에서 확인한 개념을 네 묶음으로 보고, 착각한 개념부터 다시 공부해요.

가장 잘됐을 때의 장면은 이거예요.

> **시험 전날, 아무도 시키지 않았는데 학습자가 "내 이해 기록"을 열어 "자신 있었는데 틀린 개념"부터 다시 공부한다.**

화면별 자세한 내용은 [화면 흐름](<https://linear.app/silo0/document/02-%ED%99%94%EB%A9%B4-%ED%9D%90%EB%A6%84-6dbdadb44bbb>)에 있어요.

## 확인할 가설

가설은 서로 이어져 있어요. 앞 가설이 틀리면 뒤 가설은 확인할 수 없어요. 그래서 빨리 확인할 수 있고 틀렸을 때 영향이 큰 가설부터 확인해요.

| 번호 | 가설 | 지표 | 틀리면 |
| -- | -- | -- | -- |
| H1 | 시험을 앞두고 AI로 공부하는 사람은 "진짜 아는지" 확인받고 싶어 한다 | 공부 시작 비율 | 게시글 문구나 대상을 바꿔요 |
| H2 | AI 설명을 읽은 학습자는, 자신 있다고 답한 개념도 다음 날 혼자 풀지 못하는 경우가 많다 | 착각 비율 | 문제가 작다고 보고, 인터뷰에서 본 다른 불편으로 넘어가요 |
| H3 | 다음 날 확인 화면을 띄우면, 학습자는 넘기지 않고 끝까지 푼다 | 확인 완료 비율 | 확인 화면의 위치, 문제 수, 문구를 바꿔요 |
| H4 | 확인한 기록을 네 묶음으로 보여 주면, 학습자는 시키지 않아도 기록을 다시 연다 | 기록 재방문 학습자 수 | 기록을 보여 주는 방식이나 위치를 바꿔요 |

H2는 프로토타입이 나오기 전에 인터뷰에서 손으로 먼저 확인해요. 방법은 [진행 가이드](<https://linear.app/silo0/document/03-1-%EC%A7%84%ED%96%89-%EA%B0%80%EC%9D%B4%EB%93%9C-7acec4859ba4>)의 "인터뷰"에 있어요.

## 무엇으로 판단하나요

### 지표

| 종류 | 지표 | 계산 방법 |
| -- | -- | -- |
| 핵심 지표 | 기록 재방문 학습자 수 | 첫 확인을 마친 다음 날부터, 시키지 않았는데 "내 이해 기록"을 한 번 이상 연 학습자 수 |
| 보조 지표 | 공부 시작 비율 | 커뮤니티에서 들어와 첫 질문까지 한 학습자 수 ÷ 게시글 조회 수 |
| 보조 지표 | 착각 비율 | "자신 있음"이라고 답했는데 틀린 확인 수 ÷ "자신 있음"이라고 답한 확인 수 |
| 보조 지표 | 확인 완료 비율 | 넘기지 않고 끝까지 푼 확인 수 ÷ 보여 준 확인 수 |
| 보조 지표 | 아쉬움 응답 비율 | 시험 뒤 설문에서 "더 못 쓰게 되면 매우 아쉽다"를 고른 비율 |
| 가드레일 지표 | 학습 화면 사용 일수 | 학습자가 AI에게 질문한 날의 수. 확인 화면이 귀찮아서 공부하러 오지 않으면 안 돼요 |

* "자신 있음"은 확신도 75% 이상으로 봐요.
* 지표마다 "몇이면 성공인지" 기준 숫자를 **11/5 (목) 학습자에게 열기 전에** 정해요. 그 뒤로는 발표를 본 뒤에도 바꾸지 않아요.

### 지인과 커뮤니티를 나눠서 봐요

지인은 부탁을 받아서 써요. 스스로 찾아온 사람과 결과를 섞으면 신호가 실제보다 좋게 나와요. 그래서 서비스 주소에 출처를 붙여 나눠서 기록해요.

| 출처 | 판단에 쓰는 곳 |
| -- | -- |
| 커뮤니티 | 모든 지표. "다시 오는가"는 이 집단으로만 판단해요 |
| 지인 | 착각 비율(H2), 확인 완료 비율(H3) |
| 인터뷰 참여자 | 인터뷰에서 한 말과 실제 행동 비교 |

### 발표와 최종 결과

학습자가 적어서 통계로 효과를 증명할 수는 없어요. 방향이 맞는지 보여 주는 **신호**를 봐요.

|  | 발표 (11/10) | 최종 결과 (11/20) |
| -- | -- | -- |
| 데이터 | 11/5\~11/9 낮 12시 (5일) | 11/5\~11/14 (10일) + 시험 뒤 설문 |
| 다루는 것 | 문제를 다시 정의한 과정, 프로토타입, 인터뷰 결과, 첫 신호 | H1\~H4 판단, 아쉬움 응답, 다음 가설 |

## 만드는 것과 만들지 않는 것

판단 기준은 하나예요. **이 기능이 없으면 H1\~H4 중 하나를 확인할 수 없나요?** "아니요"라면 이번에는 만들지 않아요.

| 만드는 것 | 만들지 않는 것 |
| -- | -- |
| 첫 화면 (이메일, 시험 날짜, 저장 동의) | 로그인, 신청 페이지 |
| 학습 화면 (왼쪽 학습 자료, 오른쪽 AI) | 모바일 화면 ("PC에서 열어 주세요" 안내만) |
| 질문 기록 | AI가 질문에서 개념을 자동으로 고르기 (열려 있던 단원으로 정해요) |
| 다음 날 확인 (확신도 → 문제) | AI가 확인 문제를 그때그때 만들기 (PO가 미리 만들어요) |
| 결과 화면 | 알림 (스스로 다시 오는지 봐야 해요) |
| 내 이해 기록 (네 묶음 목록) | 내 이해 기록의 상세 화면, 보상 숫자 |
| 사용 기록 | 플랫폼용 화면이나 리포트 |

학습 자료는 SQLD에서 학습자가 많이 헷갈리는 단원 3\~5개만 다뤄요. 기출문제는 그대로 옮기지 않아요.

## 역할과 결정

| 역할 | 결정하는 것 (DRI) | 이번 스프린트에서 하는 일 |
| -- | -- | -- |
| PO | 무엇을 왜 만드는지, 언제 판단하는지 | 인터뷰, 학습 자료와 확인 문제, 모집, 판단. 개발도 일부 맡아요 (내 이해 기록, 지표 추출) |
| 디자이너 | 학습자가 화면을 어떻게 보고 느끼는지 | 첫 화면, 확인 화면, 결과 화면, 내 이해 기록, 문구 |
| 개발자 | 어떻게 동작하게 만드는지 | 첫 화면, 학습 화면, AI 연결, 질문 기록, 확인 기능, 결과 화면 |

DRI는 한 영역의 최종 결정권자예요. DRI는 결정하기 전에 다른 사람의 의견을 충분히 듣고, 결정이 나면 동의하지 않았던 사람도 그 결정을 따라요. 다른 사람이 DRI인 내용을 바꾸고 싶으면 직접 고치지 말고 댓글로 제안해 주세요.

### 각자 답할 질문 하나

| 역할 | 질문 |
| -- | -- |
| 디자이너 | "자신 있었는데 틀렸다"는 순간을, 학습자가 "시험 전에 알아서 다행이다"라고 느끼게 만들 수 있는가? |
| 개발자 | 학습자의 질문과 확인 결과를, 개념 단위로 출처와 함께 빠짐없이 남길 수 있는가? |
| PO | 11/5까지 스스로 찾아올 학습자를 모을 수 있는가? |

## 지금까지 정한 것

| 결정 | 이유 |
| -- | -- |
| 문제를 "같은 개념을 또 묻는다"에서 "이해했다고 느끼지만 혼자 못 푼다"로 바꿔요 | 또 묻는 것은 신호일 뿐이고, 착각하는 사람일수록 다시 묻지 않아요 |
| 학습자가 같은 개념을 다른 날 또 물어보는 경우는 이번에 따로 다루지 않아요 | 질문 기록에는 남기 때문에, 11/20 최종 결과 때 이런 학습자가 착각을 더 많이 했는지 한 번 확인해요 |
| 학습 화면은 그대로 만들어요 | 학습자가 무엇을 공부하고 물었는지 알아야 다음 날 문제를 낼 수 있어요 |
| 이번에는 개인에게만 검증해요 | 개인에게 가치가 없는 데이터는 플랫폼에도 가치가 없어요 |
| 신청 단계 없이 바로 쓰게 해요 | "신청했다"는 말보다 "들어와서 공부했다"는 행동이 더 믿을 만해요 |
| 확인 화면을 학습 화면보다 먼저 띄워요 | 학습 화면 안에 띄우면 학습 자료에서 답을 볼 수 있어요 |
| 확신도를 문제보다 먼저 물어요 | 문제를 본 뒤에 물으면 문제 난이도가 확신도에 섞여요 |

새로 정한 것은 리니어 프로젝트 업데이트나 이슈 댓글에 남겨요.
