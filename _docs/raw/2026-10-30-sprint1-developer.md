# 스프린트1_개발자

이번 스프린트에서 개발자는 왼쪽에 학습셋, 오른쪽에 질문 창이 있는 학습 화면을 만들고, 그 위에 세 가지 기능을 붙여요. 학습자가 다시 물은 개념을 찾는 기능, 그 개념을 다음 날 학습자에게 보여 주는 기능, 결과를 빠짐없이 기록하는 기능이에요. 학습자가 8명뿐이라 기록이 한 건만 빠져도 결과를 판단하기 어려워요.

## 고민해 주셨으면 하는 것

- [ ] 학습자가 질문할 때 왼쪽에 열려 있던 단원의 내용을 AI 모델에 함께 넘겨야 해요. 어떻게 학습 자료의 맥락을 넘겨야 할까요?
- [ ] 학습자의 질문마다 개념 목록에서 개념 하나를 고를 때, 얼마나 정확하게 고를 수 있을까요? 

## 개발자의 일이 걸린 결정

"04-정할것"의 질문 중 아래 질문들은 개발자의 일에 바로 영향을 줘요. 1번과 2번은 킥오프에서 함께 정하고, 나머지는 공통 기능을 만들기 전에 함께 정해요. 결과는 "04-정할것"의 "정한 것" 표에서 확인할 수 있어요.

| 번호 | 질문 | 개발자에게 달라지는 것 |
| -- | -- | -- |
| 1 | 학습자가 무엇을 공부하게 할까 | 정했어요. 준비한 학습셋을 왼쪽에 보여 주고, 학습셋에서 뽑은 개념 목록으로 같은 개념을 판단해요 |
| 2 | 학습 에이전트를 어떻게 만들까 | 정했어요. 왼쪽 학습셋, 오른쪽 질문 창이 있는 웹을 직접 만들어요 |
| 6 | 같은 개념인지 어떻게 판단할까 | 다시 물은 개념 찾기를 만드는 방법. 질문과 열려 있던 단원을 함께 보고 고르기를 추천해요 |
| 7 | 하루를 언제부터 언제까지로 볼까 | "다음 날"과 "서로 다른 날"을 계산하는 기준. 새벽 4시를 추천해요 |
| 8 | 학습자를 어떻게 구분할까 | 로그인 방식. 구글 로그인처럼 비밀번호를 따로 만들지 않는 방식을 추천해요 |
| 9 | 다시 물은 개념을 언제부터 셀까 | 학습 에이전트가 준비되는 날부터 기록을 모아요 |

## 먼저 할 일

| 순서 | 할 일 | 이유 |
| -- | -- | -- |
| 1 | 학습 화면 만들기: 왼쪽 학습셋, 오른쪽 질문 창, AI 모델 연결, 로그인 | 학습 화면이 빨리 준비될수록 다시 물은 개념을 더 많이 모을 수 있어요 |
| 2 | 학습자의 질문 기록 만들기 | 어떤 방식으로 정해지든 학습자의 질문을 시간과 함께 저장해야 해요 |
| 3 | 다시 물은 개념 찾기 만들기 | 세 방식 모두 이 기능을 바탕으로 동작해요 |

디자이너의 화면을 받기 전에는 학습셋 불러오기, AI 모델 연결, 질문 기록부터 만들어 주세요.

다시 물은 개념 찾기가 동작하면, PM이 결과를 직접 확인하고 잘못 찾은 개념을 알려 드려요. 학습자가 8명이라 사람이 직접 확인할 수 있어요.

## 방식이 정해진 뒤에 할 일

디자이너가 돕는 화면을 넘겨주면 돕는 기능과 측정 기록을 만들어요. 상황마다 어떻게 동작해야 하는지는 "05-화면흐름"의 상황별 규칙을 따라 주세요. 아래 내용은 떠올리기 질문으로 정해졌을 때를 기준으로 썼어요.

* 학습자마다 다시 물은 개념 중 절반을 무작위로 골라, 다음 날 떠올리기 질문으로 보여 줘요. 나머지 절반은 보여 주지 않아요. 나중에 두 쪽의 결과를 비교하기 위해서예요.
* 개념이 다시 물은 개념으로 처음 찾아질 때 보여 주는 쪽인지 정하고, 그 뒤로는 바꾸지 않아요.
* 떠올리기 질문은 하루에 하나만 보여 줘요. 학습자가 다음 날 오지 않으면 다음에 올 때 보여 줘요. 알림은 보내지 않아요.
* 떠올리기 질문의 문구는 PM이 개념마다 미리 만들어 둔 것을 써요. AI로 그때그때 만들지 않아요.

측정 기록에는 아래 내용을 저장해 주세요.

| 저장할 것 | 쓰는 곳 |
| -- | -- |
| 학습자의 질문마다 시간, 학습자, 열려 있던 단원, 고른 개념 | 다시 물은 개념 찾기, 잘못 고른 개념 고치기 |
| 학습자가 왼쪽에서 연 단원과 시간 | 다시 묻지 않고 학습셋을 다시 읽은 경우 확인 |
| 개념마다 떠올리기 질문을 보여 주는 쪽인지 아닌지 | 확인 문제 결과 비교 |
| 떠올리기 질문을 보여 준 시간, 학습자가 답했는지 넘어갔는지 | 학습자가 떠올리기 질문에 답하는지 확인 |
| 학습자가 "맞았어요"를 눌렀는지 | 혼자 맞힌 개념의 숫자 보여 주기 |
| 학습자가 학습 에이전트를 연 시간 | 떠올리기 질문 때문에 학습자가 덜 오지 않는지 확인 |

## 개발자가 정할 것

| 정할 것 | 함께 정하는 사람 |
| -- | -- |
| AI 모델과 학습 에이전트의 지시문 | PM |
| 학습셋 파일을 받는 형식 | PM |
| 학습자의 질문에서 개념을 고르는 방법 | PM |
| 기록을 저장하는 구조 | 개발자가 정해요 |

## 주고받는 것

| 받는 것 | 주는 사람 | 받는 때 |
| -- | -- | -- |

| 로그인 화면과 학습 화면 (Figma 링크) | 디자이너 | 학습 화면을 만들기 전 |
| 돕는 방식 결정 | PM | 인터뷰를 마친 뒤 |

| 개념마다 떠올리기 질문 문구 | PM | 돕는 기능을 만들기 전 |

| 넘겨줄 것 | 받는 사람 | 넘겨주는 때 |
| -- | -- | -- |
| 학습자가 로그인해서 쓸 수 있는 학습 화면 주소 | PM | 학습 에이전트가 준비되면 |
| 학습자별 다시 물은 개념 목록 | PM | 다시 물은 개념 찾기가 동작하면 |

날짜는 킥오프에서 일정을 정한 뒤 이슈에 적어요.

기능을 다 만들면 PR을 열어 주세요. PR을 열면 이슈가 In Review로 옮겨지고, PM과 디자이너가 실제 화면에서 의도대로 동작하는지 확인해요. PR을 머지해도 이슈는 Done으로 옮겨지지 않아요. 확인한 사람이 직접 옮겨요.
