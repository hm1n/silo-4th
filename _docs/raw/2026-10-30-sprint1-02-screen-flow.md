# 02 화면 흐름

학습자가 어떤 화면을 어떤 순서로 보는지, 상황마다 무엇을 보여 주는지, 무엇을 기록하는지 정한 문서예요. 디자이너는 이 흐름을 바탕으로 화면을 그리고, 개발자는 이 흐름대로 동작을 만들어요.

## 누가 무엇을 정하나요

| 역할 | 정하는 것 |
| -- | -- |
| PO | 어떤 화면이 있는지, 화면이 이어지는 순서, 화면마다 보여 줄 정보, 상황별 규칙, 문구 초안 |
| 디자이너 | 화면 배치와 모양, 움직임, 문구 다듬기 |
| 개발자 | 흐름을 동작으로 만드는 방법, 기록을 저장하는 구조 |

흐름이나 규칙을 바꾸는 게 낫다고 생각되면, 직접 고치지 말고 이 문서에 댓글로 제안해 주세요.

## 화면 목록

| 화면 | 언제 보이나요 | 보여 줄 정보 | 디자인 기한 |
| -- | -- | -- | -- |
| 첫 화면 | 처음 들어왔을 때 | 서비스 소개 한 문장, 이메일, 시험 날짜, 저장 동의 | 11/2 (월) |
| 학습 화면 | 평소 공부할 때 | 왼쪽에 학습 자료, 오른쪽에 AI 질문 창, "내 이해 기록" 버튼 | 개발자가 기본 컴포넌트로 만들어요 |
| 확인: 확신도와 문제 | 어제 질문한 날, 학습 화면에 들어가기 전에 | 확신도 버튼, 개념 이름 없는 문제, "나중에 할게요" | 11/2 (월) |
| 확인: 결과 | 문제를 푼 직후 | 자신감과 실제 결과, 한 줄 설명, "다시 읽기", "공부하러 가기" | 11/3 (화) |
| 내 이해 기록 | 학습 화면에서 열었을 때 | 확인한 개념을 네 묶음 목록으로 | 11/3 (화) |

## 흐름 1. 처음 들어올 때

1. 학습자가 커뮤니티 게시글이나 지인이 보낸 주소로 들어와요. 주소에는 출처가 붙어 있어요.
2. 첫 화면에서 이메일, 시험 날짜를 입력하고 저장에 동의해요.
3. 학습 화면으로 이동해요. 왼쪽에는 첫 단원이 열려 있고, 오른쪽에는 "읽다가 궁금한 게 생기면 편하게 물어보세요"가 보여요.

다른 기기나 브라우저에서 같은 이메일을 입력하면 같은 학습자로 이어져요.

## 흐름 2. 공부할 때

1. 학습자가 왼쪽에서 단원을 골라 읽어요.
2. 궁금한 게 생기면 오른쪽 질문 창에 물어봐요.
3. AI가 그때 열려 있던 단원의 내용을 알고 바로 답해요. 답을 숨기거나 되묻지 않아요.
4. 질문은 시간, 열려 있던 단원과 함께 기록돼요. 학습자에게 기록 표시를 따로 보여 주지 않아요.

## 흐름 3. 다음 날 확인할 때

1. 어제 질문한 단원이 있으면, 학습 화면에 들어가기 전에 확인 화면이 전체 화면으로 떠요.
2. 문제를 보여 주기 전에 확신도부터 물어요.
3. 학습자가 확신도를 고르면 문제가 나와요. 문제는 객관식이고, 개념 이름이 나오지 않아요.
4. 학습자가 답을 고르면 결과 화면으로 넘어가요.
5. 결과 화면에서 자신감과 실제 결과를 나란히 보여 줘요.
6. 문제가 더 있으면 2번으로 돌아가요. 하루 최대 3문제예요.
7. "다시 읽기"를 누르면 그 단원이 열린 학습 화면으로, "공부하러 가기"를 누르면 마지막에 보던 학습 화면으로 가요.

**확인 화면을 학습 화면보다 먼저 띄우는 이유:** 학습 화면 안에 띄우면 학습자가 왼쪽 학습 자료에서 답을 보고 풀 수 있어요. 그러면 혼자 풀 수 있는지 확인할 수 없어요.

**확신도를 문제보다 먼저 묻는 이유:** 문제를 본 뒤에 물으면, 학습자는 문제의 난이도를 보고 확신도를 정해요. 우리가 알고 싶은 것은 "공부한 내용을 안다고 느끼는 정도"예요.

## 흐름 4. 내 이해 기록을 볼 때

1. 학습자가 학습 화면에서 "내 이해 기록"을 열어요.
2. 지금까지 확인한 개념이 네 묶음 목록으로 보여요.
3. 개념을 누르면 그 개념의 단원이 열린 학습 화면으로 가요.

| 묶음 | 기준 | 순서 |
| -- | -- | -- |
| 자신 있었는데 틀린 것 | 확신도 75% 이상 + 틀림 | 맨 위 |
| 아직 모르는 것 | 확신도 75% 미만 + 틀림 | 두 번째 |
| 맞았지만 불안한 것 | 확신도 75% 미만 + 맞음 | 세 번째 |
| 확실히 아는 것 | 확신도 75% 이상 + 맞음 | 맨 아래 |

같은 개념을 여러 번 확인했으면 가장 최근 결과로 묶어요.

## 상황별 규칙

| 상황 | 보여 줄 것 |
| -- | -- |
| 어제 질문하지 않았어요 | 확인 화면 없이 학습 화면으로 가요 |
| 며칠 만에 들어왔어요 | 가장 최근에 질문한 날의 단원으로 확인 화면을 띄워요 |
| 어제 질문한 단원이 여러 개예요 | 하루 최대 3문제까지 보여 줘요 |
| 오늘 이미 확인을 끝냈어요 | 다시 들어와도 확인 화면을 띄우지 않아요 |
| "나중에 할게요"를 눌렀어요 | 학습 화면으로 가요. 그날 다시 들어오면 한 번 더 띄워요 |
| 문제를 풀다가 화면을 닫았어요 | 다음에 들어오면 푼 문제 다음부터 이어서 보여 줘요 |
| 확인한 개념이 아직 없어요 | 내 이해 기록에 "내일부터 확인한 개념이 여기에 모여요"를 보여 줘요 |
| AI가 답하지 못했어요 | "답을 가져오지 못했어요. 다시 보내 주세요."를 보여 줘요 |
| 모바일로 들어왔어요 | "PC에서 열어 주세요"를 보여 줘요 |
| 저장에 동의하지 않았어요 | 학습 화면으로 넘어가지 않아요. 기록이 이 서비스의 핵심이라서 동의가 필요하다고 안내해요 |

하루의 시작은 새벽 4시로 봐요. 밤 11시부터 새벽 1시까지 공부한 학습자의 하루가 둘로 나뉘지 않게 하려는 거예요.

## 화면 배치 예시

무엇이 어떤 순서로 보이는지만 참고해 주세요. 모양과 배치는 디자이너가 정해요.

**확인: 확신도와 문제**

```
┌──────────────────────────────────────────────────────┐
│ 어제 공부한 내용, 오늘 확인해 볼까요?       (1 / 3)     │
│                                                      │
│ ① 어제 공부한 [단원] 내용이 문제로 나오면,               │
│   맞힐 자신이 얼마나 있나요?                            │
│   [ 0% ][ 25% ][ 50% ][ 75% ][ 100% ]                 │
│                                                      │
│ ─ 확신도를 고르면 아래가 열려요 ─                        │
│                                                      │
│ ② [개념 이름이 나오지 않는 상황형 문제]                   │
│   ○ 보기 1   ○ 보기 2   ○ 보기 3   ○ 보기 4            │
│                                     [나중에 할게요]    │
└──────────────────────────────────────────────────────┘
```

**확인: 결과**

```
┌──────────────────────────────────────────────────────┐
│  내 자신감  75%        실제 결과  틀렸어요              │
│                                                      │
│  자신 있었는데 틀렸어요.                                │
│  시험 전에 찾아서 다행이에요.                           │
│                                                      │
│  [왜 틀렸는지 한 줄 설명]                               │
│        [다시 읽기]            [공부하러 가기]            │
└──────────────────────────────────────────────────────┘
```

## 문구 초안

디자이너가 화면에 맞게 다듬어 주세요. 뜻이 바뀌면 PO에게 알려 주세요.

| 자리 | 문구 |
| -- | -- |
| 첫 화면 소개 | 오늘 AI에게 물어본 내용, 내일 진짜 혼자 풀 수 있는지 확인해 드려요 |
| 저장 동의 | 공부하며 남긴 질문과 확인 결과를 저장하고 분석하는 데 동의해요 |
| 질문 창 첫 안내 | 읽다가 궁금한 게 생기면 편하게 물어보세요 |
| 확인 화면 제목 | 어제 공부한 내용, 오늘 확인해 볼까요? |
| 확신도 질문 | 어제 공부한 \[단원\] 내용이 문제로 나오면, 맞힐 자신이 얼마나 있나요? |
| 넘기기 버튼 | 나중에 할게요 |
| 결과: 확실히 아는 것 | 확실히 알고 있어요 |
| 결과: 자신 있었는데 틀린 것 | 자신 있었는데 틀렸어요. 시험 전에 찾아서 다행이에요 |
| 결과: 맞았지만 불안한 것 | 맞았지만 아직 불안해요. 한 번 더 보면 확실해져요 |
| 결과: 아직 모르는 것 | 아직 모르는 걸 정확히 알고 있었어요 |
| 내 이해 기록 빈 상태 | 내일부터 확인한 개념이 여기에 모여요 |

## 남겨야 할 기록

기록은 지표를 계산하는 데 쓰고, 동시에 프로젝트의 핵심 자산이에요. 학습자가 적어서 기록이 한 건만 빠져도 판단하기 어려워요. 저장 구조는 11/2 (월) 오전에 PO와 개발자가 함께 정해요.

| 기록 | 내용 |
| -- | -- |
| 학습자 | 이메일, 시험 날짜, 저장 동의, 출처(커뮤니티, 지인, 인터뷰), 처음 들어온 시간 |
| 질문 | 시간, 학습자, 질문 내용, 질문할 때 열려 있던 단원 |
| AI의 답 | 답 내용, 답한 시간 |
| 확인 | 학습자, 단원, 문제, 확신도, 고른 보기, 맞았는지, 확인 화면을 보여 준 시간, 끝까지 풀었는지 넘겼는지 |
| 이해 상태 | 개념마다 네 묶음 중 어디에 속하는지, 바뀐 시간 |
| 사용 | 학습 화면에 들어온 시간, 내 이해 기록을 연 시간 |

## 확인 문제의 형식

PO가 단원마다 미리 만들어서 11/3 (화) 저녁까지 넘겨요.

| 항목 | 내용 |
| -- | -- |
| 형식 | 객관식, 보기 4개 |
| 문제 | 개념 이름이 나오지 않는 상황형 문제 |
| 보기 | 정답 1개, 오답 3개. 오답마다 흔한 오해를 하나씩 담아요 |
| 한 줄 설명 | 결과 화면에 보여 줄 "왜 그런지" 설명 |
| 연결 | 문제가 어느 단원, 어느 개념에 속하는지 |
