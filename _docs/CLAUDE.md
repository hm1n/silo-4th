# docs 작업 규칙

## 폴더

- `raw/`는 원본 자료를, `wiki/`는 원본을 정리한 지식 문서를, `output/`은 외부 공유용 산출물을 보관한다.
- `index.md`에는 미션, 폴더 구조와 역할, 탐색 순서처럼 바뀌지 않는 내용만 둔다. 개별 문서 목록이나 PRD처럼 바뀔 수 있는 내용은 넣지 않는다.
- 문서를 찾을 때는 `index.md` → `log.md` 최근 줄 → `wiki/` → `raw/` 순서로 본다.

## 기준 자료

- 원본이 서로 다르면 Linear의 현재 스프린트 프로젝트 문서(지금은 "스프린트 1: 이해 확인과 기록 검증")를 우선한다. PRD와 팀 문서의 draft는 배경 자료로만 쓴다.
- Linear 문서는 raw에 저장하지 않고 Linear에서 바로 조회한다. Linear가 문서의 수정 기록과 이전 버전을 남기기 때문이다. wiki의 근거에는 Linear 문서 링크를 단다.

## raw

- Linear에 없는 원본(대화로 정한 결정, 외부 자료 등)만 저장한다.
- 파일명은 `{YYYY-MM-DD}-{주제}.md`로 짓는다. 같은 날 같은 주제를 다시 저장하면 끝에 `-v2`, `-v3`을 붙인다.
- frontmatter에 출처 링크, 저장 날짜, 원문 수정 시각을 남긴다. 수정 시각이 이전 스냅샷과 같으면 다시 저장하지 않는다.
- 저장한 파일은 frontmatter를 포함해 고치지 않는다. 오류를 발견하면 별도 메모에 적는다.
- 다른 원본으로 대체되면 파일은 그대로 두고, `log.md`에 대체된 파일과 대체한 자료를 적는다.

## wiki

- 핵심 주장마다 근거 위치를 남기고, 근거가 부족하면 `확인 필요`로 표시한다.
- 결정에는 정한 사람(PO, 디자이너, 개발자)을 함께 적고, 아직 정하지 않은 내용은 `제안`으로 표시한다.
- 자료가 서로 충돌하면 하나로 합치지 말고 충돌 사실을 적는다.
- ADR에는 기록 저장 구조나 AI 모델처럼 개발자가 정하는 결정만 기록한다.
- 개발 규칙이나 ADR을 추가하거나 고치면 `wiki/dev-rules.md`에도 반영해, 모든 개발 규칙을 그 문서 하나에서 볼 수 있게 한다.

## output

- 수정이 필요하면 기존 문서를 고치지 않고 새 버전을 만든다. 근거는 `wiki/`나 `raw/` 링크로 단다.

## 민감 정보

- 학습자에게 공개하는 서비스 주소와 학습자의 이메일, 질문 원문, 확인 기록 원본은 `_docs`에 저장하지 않는다. 지표는 집계한 숫자만 남긴다.
- 민감 정보가 담긴 자료는 외부 전송이나 웹 검색에 쓰지 않는다.

## 로그

- 자료를 추가하거나 문서를 만들 때마다 [`log.md`](log.md)에 `날짜 | 작업 | 결과 | 확인 필요` 형식으로 한 줄을 남긴다. 기존 줄은 지우지 않고, 되돌릴 내용은 새 줄로 적는다.

## 작성

- 보고서나 실행 계획을 쓸 때는 관련 `wiki/` 문서를 먼저 확인하고, 근거가 있는 내용과 추정을 구분한다.
- 완성된 문장으로 쓴다. '~임, ~함' 같은 명사형 종결 어미를 쓰지 않는다.
