# 기술 스택

## 한 문장 요약

2주 실험용 학습 에이전트는 Next.js, Vercel, Anthropic 공식 SDK, Tailwind CSS로 최소한만 구성하고, DB는 핵심 기능이 정해진 뒤에 도입 여부를 판단한다.

- 확인 날짜: 2026-10-28

- 관련 문서: [docs 목차](../index.md)

## 스택을 정할 때 고려한 조건

- 개발자 1명이 7일차까지 기능 다섯 가지를 만들어야 한다. (PRD 5장 역할별 2주 일정)
- 로그인은 참여 코드로 대신한다. (PRD 5장 간단하게 만들 학습 에이전트)
- 대시보드는 스프레드시트로 대신한다. (PRD 5장)
- 화면 완성도는 이번 범위에 들어가지 않는다. (PRD 5장)
- 개발자는 주로 React와 Next.js를 사용한다. (논의 결과)
- LLM은 Anthropic API를 사용하며, 상황에 따라 모델을 바꿀 수 있다. (논의 결과)

## 확정한 스택

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 프레임워크 | Next.js(App Router)와 TypeScript | 개발자에게 익숙한 도구다. 화면과 API를 한 저장소에서 만들 수 있어서 혼자 7일 안에 끝내기에 알맞다 |
| 배포 | Vercel | Next.js를 별도 설정 없이 배포할 수 있고, 배포 링크를 바로 참여자 8명에게 전달할 수 있다 |
| LLM 연결 | `@anthropic-ai/sdk` | Anthropic만 사용하므로 다른 회사 모델로 바꾸는 기능이 필요 없다. 공식 SDK라서 구조화 출력이나 effort 같은 Claude 기능을 바로 쓸 수 있다 |
| 모델 | Claude Opus 5.5(`claude-opus-5-5`)를 기본값으로 둔다 | 모델 ID만 바꾸면 Sonnet 5.5나 Haiku 5.5로 전환할 수 있다. 어떤 작업에 어떤 모델을 쓸지는 개발자가 정한다 |
| 지표 확인 | Google Sheets | PRD에서 대시보드 대신 스프레드시트를 쓰기로 했다 |
| 스타일 | Tailwind CSS | 화면 완성도가 범위 밖이므로 빠르게 만드는 쪽을 택했다. shadcn/ui는 필요할 때 추가한다 |

## 넣지 않은 것

| 제외한 것 | 이유 |
| --- | --- |
| 인증 서비스 | 로그인 대신 참여 코드를 쓰기 때문이다 (PRD 5장) |
| 대시보드 도구 | 스프레드시트로 대신하기 때문이다 (PRD 5장) |
| Vercel AI SDK | Anthropic만 사용하므로 다른 모델로 바꾸는 기능이 필요 없다. 대신 채팅 스트리밍은 직접 연결해야 한다 |

## 보류한 것

- **DB:** 핵심 기능이 아직 구체화되지 않아 필요한지 판단하기 이르다. 도입이 반드시 필요하다고 판단되면 그때 정한다. 논의 중에는 Supabase나 Neon 같은 Postgres가 후보로 나왔다.

## 확인 필요

- Google Sheets에 데이터를 어떤 방식으로 옮길지는 DB 도입 여부와 함께 정해야 한다.
- 대화 원문을 저장할지는 구현을 구체화하면서 정한다. 인터뷰에서는 원문을 받지 않지만(PRD 5장, 7장), 에이전트 안의 대화에 같은 원칙을 적용할지는 아직 정하지 않았다.
