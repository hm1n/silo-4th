# 0003. 기록 저장은 Neon Postgres에 하고, Drizzle ORM으로 접근한다

- 상태: 확정
- 결정 날짜: 2026-10-30
- 결정한 사람: 개발자
- 수정: 2026-11-02, 4-48 로그인에서 학습자와 계정을 함께 저장해야 해 드라이버를 HTTP 방식에서 Pool 방식으로 바꿨다
- 관련 문서: [스프린트 1 기술 스택 결정](../../raw/2026-10-30-tech-stack-decisions.md), [기술 스택](../tech-stack.md), [0001. AI 코딩 규칙은 md보다 검사 도구로 강제한다](0001-ai-coding-rule-enforcement.md)

## 상황

02 화면 흐름은 학습자, 질문, AI의 답, 확인, 이해 상태, 사용의 기록 여섯 가지를 빠짐없이 남기도록 정했다. 다른 기기에서 같은 이메일을 입력하면 같은 학습자로 이어지고, 문제를 풀다 닫으면 다음에 이어서 풀어야 하므로 기록은 서버에 있어야 한다. PO는 이 기록에서 지표를 추출한다. 기록 구조는 11/2 오전에 PO와 확정하고, 만드는 기간은 11/2부터 11/4까지 사흘이다. (근거: [02 화면 흐름](https://linear.app/silo0/document/02-화면-흐름-6dbdadb44bbb) "남겨야 할 기록", [03 상세 일정](https://linear.app/silo0/document/03-상세-일정-1f1a08402713))

기존 기술 스택은 DB를 보류했고, Supabase와 Neon을 후보로 두었다.

## 결정

DB는 Neon Postgres를 쓰고, 코드에서는 Drizzle ORM으로 접근한다. 스키마는 Drizzle 스키마 파일 하나에 정의하고, 이 파일을 기록 구조의 기준으로 삼는다.

## 검토한 대안

| 대안 | 장점 | 단점 | 택하지 않은 이유 |
| --- | --- | --- | --- |
| Supabase | 테이블 편집 화면이 있어 SQL 없이 데이터를 볼 수 있다 | 인증, 스토리지 같은 기능은 이번에 쓰지 않는다 | 필요한 것은 Postgres뿐이고, Neon이 Vercel에 연결하기 더 단순하다 |
| SQL 직접 작성 (`@neondatabase/serverless`) | 의존성이 가장 적고 PO의 지표 쿼리와 같은 문법을 쓴다 | 결과 행의 타입을 손으로 붙여야 하고, 컬럼 이름 오타는 실행해야 드러난다 | AI가 쓴 DB 코드를 검사 도구로 잡을 수 없어 0001의 원칙과 맞지 않는다 |
| Prisma | 널리 쓰이는 ORM이다 | 설정과 코드 생성 단계가 더 필요하다 | 사흘 일정에 무겁다 |

## 결과

- 스키마에서 타입이 나와, AI가 없는 컬럼을 쓰거나 타입을 잘못 넘기면 `npm run check`가 실패한다.
- 스키마를 고치면 Drizzle 도구로 DB에 반영할 수 있어 사흘 동안 기록 구조가 바뀌어도 대응하기 쉽다.
- 테이블은 평범한 Postgres 테이블이라 PO가 SQL로 지표를 뽑을 수 있다.
- `drizzle-orm`, `drizzle-kit`, Neon 드라이버가 의존성에 추가된다.

2026-10-30 연결 때 정한 내용: 드라이버는 의존성이 가장 적은 HTTP 방식(`drizzle-orm/neon-http`, `@neondatabase/serverless`)을 쓴다. 이 방식은 대화형 트랜잭션을 지원하지 않으므로, 11/2 기록 구조 회의에서 여러 기록을 함께 저장해야 한다고 정하면 `lib/db/index.ts` 한 파일을 Pool 방식으로 바꾼다. DB 클라이언트는 `getDb()`를 처음 부를 때 만들어, 빌드 환경에 `DATABASE_URL`이 없어도 빌드가 통과한다. Neon 프로젝트는 Vercel Marketplace가 아니라 개발자 계정에 만든다. Marketplace로 만들면 접근 권한을 Vercel 팀이 관리하는데, Hobby 요금제는 PO를 팀에 추가할 수 없어 PO가 콘솔에서 SQL을 실행하지 못할 수 있기 때문이다(확인하지 않은 추정).

2026-11-02 변경: 위 조건대로 `lib/db/index.ts`의 드라이버를 Pool 방식인 `drizzle-orm/neon-serverless`로 바꿨다. 4-48 로그인에서 Better Auth가 첫 로그인 때 학습자와 로그인 계정을 차례로 저장하는데, 트랜잭션 없이 계정 저장만 실패하면 계정이 연결되지 않은 학습자가 남는다. 계정 자동 연결을 꺼 두었으므로 그 학습자는 다시 로그인할 수 없다. test 브랜치에서 계정 저장만 실패하게 만들어 보니, 트랜잭션을 끄면 학습자 행이 1개 남고 켜면 0개였다. 필요한 패키지는 이미 설치되어 있었고, Node 24에 WebSocket이 기본으로 들어 있어 추가 설정은 없다. `getDb()`를 처음 부를 때 만드는 방식은 그대로다. 이제 다른 기능도 `getDb().transaction()`으로 여러 기록을 함께 저장할 수 있다. Pool은 쉬던 연결이 끊기면 `error` 이벤트를 내고, 받는 곳이 없으면 Node가 프로세스를 끝낸다. 그래서 `getDb()`가 Pool을 만들 때 오류 처리를 달아 오류 메시지만 서버 로그에 남긴다. 끊긴 연결의 오류에는 쿼리 값이 담기지 않는다. test 브랜치에서 쉬던 연결에 오류를 보내 보니 오류 처리를 단 Pool은 다음 쿼리를 정상 처리했고, 오류 처리가 없는 Pool은 예외를 던졌다.

## 다시 검토할 조건

- PO가 코드를 다루지 않고 SQL로만 데이터를 넣어야 해서 Drizzle 스키마와 실제 테이블을 맞추기 어려워지면 다시 본다.
